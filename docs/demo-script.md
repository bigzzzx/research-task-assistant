# 演示录屏脚本（3–5 分钟）

提交用的成片是 `recordings/AI生成的演示视频.mp4`（3 分 14 秒），由本脚本自动录制。录制使用真实 DeepSeek 模型、真实本机子进程和真实 SQLite，没有使用测试替身。

## 一 分镜

字幕条固定在画面底部，内容与下表“字幕”一致；鼠标位置有高亮圆点，方便看清点击位置。

| 步骤 | 画面 | 字幕 |
| --- | --- | --- |
| 00 开始 | 登录页 | 本机运行的研究助手：用中文对话提交 FASTA 分析，工具调用全程可见。 |
| 01 登录 | 输入用户名密码进入工作区 | 账号彼此隔离：会话、上传文件、任务和工具开关都按账号保存。 |
| 02 新建会话 | 左侧历史会话、中间输入框、右侧样例与任务 | 新建会话，直接说出想做的分析。左侧是历史会话列表，右侧是样例文件和任务状态。 |
| 03 提交任务 | 发送“帮我统计一下 sample1 里序列的 GC 含量。”，工具卡陆续出现 | 助手自己调用 submit_job（seq_stats + sample1.fasta）拿到任务 ID，再查状态、读日志。 |
| 04 自动读取结果 | 任务卡变为成功，助手输出解释 | 任务结束后助手读取 stdout，用自然语言解释；右侧任务卡可以下载完整日志。 |

| 12 上传文件 | 点「上传 FASTA」，选择 `my_sequences.fasta` | 上传自己的 FASTA，文件进入当前账号的「我的文件」，可以被任一会话复用。 |
| 13 分析上传文件 | 发送“用 seq_stats 分析我上传的 my_sequences.fasta。” | 直接用自然语言指定上传的文件，走的还是同一套三个工具。 |
| 14 上传结果 | 三条序列的统计表 | 上传文件和内置样例没有区别：提交、等待、读日志、解释，结果同样落进任务记录。 |
| 15 刷新恢复 | 刷新页面 | 刷新页面：会话、消息、工具记录和任务状态都从 SQLite 恢复，不依赖浏览器缓存。 |
| 16 历史会话 | 左侧切换会话 | 左侧可以切换历史会话；刚上传的文件也还在。 |

## 二 录制方式

1. 用独立数据目录启动后端（避免影响日常 `var/`）：

   ```powershell
   $env:APP_DATA_DIR='demo-data'
   .\.venv\Scripts\python.exe -m uvicorn backend.app.api:app --host 127.0.0.1 --port 8790
   ```

2. 用 Playwright 驱动 Chromium 录制 1440×960 的视口（本机开发依赖，不属于应用依赖）：

   ```powershell
   .\.venv\Scripts\python.exe -m pip install playwright
   .\.venv\Scripts\python.exe -m playwright install chromium
   .\.venv\Scripts\python.exe demo\record_demo.py --base-url http://127.0.0.1:8790 --pace 2.4
   ```

   `demo/record_demo.py` 会：

   - 用脚本预先创建演示账号（`demo` / `demo1234`），视频里只演示登录；
   - 在页面里注入底部字幕条和鼠标高亮（仅录屏用，不改应用）；
   - 按真实状态等待（流式结束、任务终态、结果出现），而不是固定 sleep 猜时间；
   - 把每段字幕的开始时间写入 `recordings/timeline.json`，便于后期配音对齐；
   - 原始 `.webm` 落在 `recordings/raw/`（已被 `.gitignore` 排除）。

   `--pace` 只放大字幕停留时间，用来把成片控制在 3–5 分钟；任务和模型的实际耗时不受影响。

3. 转码为 MP4：

   ```powershell
   ffmpeg -i recordings/raw/<录制文件>.webm -c:v libx264 -preset slow -crf 25 -pix_fmt yuv420p -movflags +faststart -an "recordings/AI生成的演示视频.mp4"
   ```

   如需配音，按 `recordings/timeline.json` 里每段的 `at` 秒数放置音频（`adelay` 与 `amix`），字幕文本就是讲解词。

## 三 为什么这样录

- **用真实模型和真实子进程**：画面里出现的任务 ID、日志行号、GC 数值都能在任务管理和 `var/` 里复查，不是预录的假数据。
- **演示脚本只驱动界面**：所有分析都走后端和 MCP 工具链，和人工点击完全同一条路径。
- **失败场景保留原始日志**：sample3 的两条诊断（缺标题行、非法字符列区间）来自脚本 stderr，助手只是把它们翻译成自然语言；修复预览也由后端生成，界面只负责展示。

## 四 人工讲解版

`recordings/演示视频讲解.mp4` 是 1920×1080、带语音的完整操作讲解（8 分 19 秒），覆盖登录、两次分析、sample3 失败诊断、上传文件和任务管理，语速较慢、包含更多设计说明。

它作为补充材料随仓库提供，不替代 3–5 分钟的提交版：评审要求的时长以 `AI生成的演示视频.mp4`（3 分 14 秒）为准。人工版是整屏录制，发布前如涉及桌面信息可先裁剪画面。
