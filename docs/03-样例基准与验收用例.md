# 科研计算任务助手样例基准与验收用例

这份文档可在开发时直接用作断言清单。先用题面的三份原始输入核对脚本，再沿聊天界面检查模型是否选对工具、引用了正确任务的日志，并把结果说清楚。

## 一 题面给出的期望和本次复算

题面的参考对话明确了两件事。对 `sample1`，助手提交统计任务、查到成功、读取结果，并报告共有两条序列。随后用户说“再对 sample3 做一次”，助手应找出缺失标题和非法字符，给出修正建议。题面没有列出每条记录的 GC 百分比，也没有给 `sample2` 的 ORF 数值。[考题第四节期望效果示例](<../智能体开发实践考题 (1).docx>)

下表是从 Word 原始表格逐行读取后，在本机按本节口径独立复算的参考值。GC 由碱基计数复算，ORF 坐标用逐起点枚举和独立的模式匹配交叉核对。两种 ORF 算法得到相同的候选集合。后续项目脚本的实测结果应与下表比较。

| 输入文件 | 序列 ID | 长度（nt） | G+C 个数 | GC 含量 | 最长 ORF 起点 | 终点 | ORF 长度（nt） |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `sample1.fasta` | `seq1` | 45 | 22 | 48.89% | 1 | 45 | 45 |
| `sample1.fasta` | `seq2` | 47 | 29 | 61.70% | 30 | 47 | 18 |
| `sample2.fasta` | `gene_A` | 94 | 50 | 53.19% | 6 | 83 | 78 |
| `sample2.fasta` | `gene_B` | 41 | 18 | 43.90% | 7 | 21 | 15 |

`seq2` 在 5–19 还有一个 15 nt 的候选，正确答案应选 30–47 的 18 nt。`gene_A` 在 FASTA 中分占两行，连续坐标 6–83 跨过换行，长度为 `83 − 6 + 1 = 78`。这两条记录能分别发现“取第一个 ORF”和“逐行重置坐标”的实现错误。

## 二 计算口径

| 项目 | 建议首版采用的规则 |
| --- | --- |
| FASTA 与 ID | 每条记录以 `>` 引出标题，取标题第一个字段为 ID，之后各行拼成连续序列。接受大小写和常见换行。空文件、空标题或空序列报告输入错误并定位记录或行 |
| 碱基与长度 | 接受 DNA 的 IUPAC 字母 `ACGTRYSWKMBDHVN`。长度计入所有合法字母，保留输入记录的顺序。`X`、数字和其他非法字符须报告 |
| GC 含量 | 对可以明确读作 A、C、G、T 的碱基，计算 `100 × (G+C) / (A+C+G+T)`，显示两位小数。其余合法歧义碱基计入长度、排除在 GC 分母外。分母为 0 时输出 `null`，显示“没有确定碱基，无法计算”。四条题面合法记录均没有歧义碱基 |
| ORF | 只扫描正链从第 1、2、3 个碱基开始的三个阅读框。仅接受以 `ATG` 开始、在同一阅读框的首个 `TAA/TAG/TGA` 结束的完整区间，长度不设下限。遇含歧义碱基的密码子时中断该框当前候选，之后可重新起始 |
| 坐标与并列 | 起点和终点均从 1 计数，包含终止密码子的最后一个碱基，长度单位为 nt（核苷酸）。每条序列输出最长一条，等长时取起点最小者。没有完整 ORF 时返回该 ID 和 `orf: null`，任务仍成功 |

这些是可复现的产品约定。NCBI 的 FASTA 说明允许序列换行和 IUPAC 符号，ORFfinder 也提供多种起始密码子设置。面谈时应能解释首版选择的规则以及它们对含歧义碱基输入的影响。[NCBI FASTA 格式](https://www.ncbi.nlm.nih.gov/genbank/fastaformat/) · [NCBI ORFfinder](https://www.ncbi.nlm.nih.gov/orffinder/) · [NCBI 标准遗传密码表](https://www.ncbi.nlm.nih.gov/Taxonomy/Utils/wprintgc.cgi#SG1)

## 三 坏文件必须留下哪些证据

| `sample3.fasta` 原始位置 | 观察 | 建议记录 |
| --- | --- | --- |
| 第 1 行 | `seq_bad missing header marker` 前没有 `>`，第一条记录缺少合法标题 | `MISSING_HEADER`，行号 1 |
| 第 2 行 | `XXX` 位于第 7–9 列，`123` 位于第 16–18 列 | `INVALID_BASE`，行号 2，列出 `X` 和数字 `1、2、3` |
| 第 3–4 行 | `>seq_ok` 是合法标题，其序列可读 | 整份文件有错误，任务标为 `failed`，即使后面还有合法记录也不能返回整份成功 |

从聊天输入“再对 sample3 做一次”开始，检查工具轨迹中有新的 `submit_job(seq_stats, sample3.fasta)`、针对新 ID 的 `job_status` 和助手主动发起的 `read_log`。错误日志应含上面两项，最终回复给出具体修正动作。示例措辞如下。

> 这次统计没有完成。第一行是序列说明，开头缺少 FASTA 标题用的 `>`。第二行的 `X` 和数字 `1、2、3` 也无法按 DNA 碱基读取。请先在第一行开头补上 `>`，再对照原始记录核实第二行的字符，保存后重新提交。

这条用例同时检查输入校验是否收集多处错误、后端是否保留错误输出，以及助手是否能根据本次日志做解释。换一个文件名重复测试，诊断仍应由文件内容触发。

## 四 开发验收清单

下列均为**待执行用例**。A01–A07 和 A12 覆盖考题必做功能与提交要求。A08、A09 对应两项标黄加分功能。A10、A11、A13 是本方案建议的回归检查。验收时记录实际输入、任务 ID、结果和证据，分别注明真实模型联调、可控模型替身测试或独立脚本测试。

| 编号 | 操作和条件 | 通过标准 |
| --- | --- | --- |
| A01 成功对话 | 使用真实模型，在新会话请求统计 `sample1` 的 GC | 收到 ID，看到 `submit_job → job_status → read_log` 的调用与返回。正文增量显示，共两条，按 ID 报出 45 nt／48.89% 和 47 nt／61.70%，和 stdout 一致 |
| A02 两个脚本 | 分别对 `sample1`、`sample2` 运行统计和 ORF，再用自然语言请求 `sample2` 的最长 ORF | 四组脚本输出逐行匹配基准表。聊天答复中 `gene_A` 为 6–83、78 nt，`gene_B` 为 7–21、15 nt，注明坐标口径 |
| A03 失败与上下文 | 紧接 A01 发送“再对 sample3 做一次”，不主动索要日志。另对相同内容的改名副本测试 | 沿用 `seq_stats` 并给新 ID。任务失败。实际的 `read_log` 记录先于解释出现，答复指出两处问题及修正建议。两个脚本直接读取坏文件都以非零码结束 |
| A04 异步执行 | 对两个脚本分别提交，在其模拟延时内查看状态并发送另一条消息 | 提交回执早于子进程退出，两份脚本入口各有 3–5 秒延时。能观察 `running`，界面能发消息或切换会话，已有任务独立完成。实测同时记录提交时间与进程结束时间 |
| A05 会话持久化 | 创建 A、B 两个会话，分别完成不同请求，切换、刷新，再正常重启后端 | 左栏、消息顺序、可展开的工具参数和返回、任务归属均可恢复。在 B 中询问尚未指定的任务时，不拿 A 的任务回答 |
| A06 ReAct 与流式界面 | 真模型跑一次工具往返，再以可控模型替身发送分片参数、一次多个独立调用、非法工具参数 | 真实会话可看到模型请求、本地执行、对应观察及后续回答。正文结束前可见增量。工具在参数齐全后执行，每个调用的 ID、参数、返回一一对应，错误能结束或纠正 |
| A07 工具边界 | 读取超长 stdout/stderr，分别查询不存在和不属于本会话的任务，提交未知分析类型 | 两路日志有限长和各自的截断标记，头尾证据可见。错误返回明确，界面不把无效提交显示成运行中的任务 |
| A08 主动通知（标黄加分） | 分别启动一个成功任务和一个失败任务，等待其中一个完成，另一项运行时切换会话并断开再恢复页面连接 | 不追加提问即收到终态。当前会话显示结果，非当前会话有提示，重新进入可见正确日志和解释。重连后同一任务的最终消息仅一条 |
| A09 上传（标黄加分） | 上传不同于内置文件名的多行 FASTA，再通过对话分析。另试坏 FASTA、超限文件、同名文件 | 文件名可引用，多行计算正确。坏文件走完整失败流程，超限或重名有明确可执行的提示，原文件保存完好 |
| A10 分析边界 | 对下节的短输入执行纯函数测试，再对空标题、空序列、空文件执行脚本测试 | 统计、并列、缺终止、歧义和坐标都按约定输出。格式错误有行号或文件级原因 |
| A11 模型服务异常 | 使用无效配置或可控超时，并在一项已完成任务上重试解释 | 页面区分模型调用失败和脚本失败。真实任务和日志仍可查，恢复配置后可解释原任务，无重复计算 |
| A12 可交付性 | 从干净目录按 README 启动，配置自己的 Key，重走成功与失败对话并检查录屏、源码和 Git 历史 | 启动步骤完整、仓库无密钥、录屏 3–5 分钟且展示 `sample3` 失败处理，README 有架构与取舍。[交付清单](04-三天排期与交付计划.md) |
| A13 重试和中断 | 重放同一提交消息，之后主动再发一次。在另一个运行中的任务上重启后端 | 网络重试返回同一 ID，主动重提得到新 ID。重启前未确认的任务标为中断失败，能够读到运行器说明，完成解释与提示不会重复 |

## 五 单元测试的最小边界集

以下每个字符串代表一条有合法标题的记录。测试格式错误时再单独构造坏标题或空文件。

| 输入或情形 | 应观察到的输出 |
| --- | --- |
| 小写、多行 `ac` 和 `gn` | 长度 4，明确碱基 3 个，GC 为 66.67% |
| `NNN` | 长度 3，GC 为 `null`，ORF 为 `null` |
| `ATGTAAATGTAG` | 两段完整 ORF 均为 6 nt，选 1–6 |
| `ATGAAA` 或 `ATGATAA` | 前者无终止，后者终止不在同框，均返回 `orf: null` |
| `ATGNNNTAA` | 含歧义的密码子使该候选中断，按首版口径返回 `orf: null` |

验收真实模型时，以实际工具轨迹、任务状态和准确数值为准，允许中文措辞变化。模型替身适合稳定复现边界，真实 API 和浏览器行为在交付前分别实测。[技术方案](02-技术调研与开发方案.md) · [三天排期](04-三天排期与交付计划.md)
